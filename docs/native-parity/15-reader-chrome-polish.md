# Reader chrome controls polish

**Done.** Implemented and committed as `8a14767` on `feat/native-ui-web-parity`, 2026-07-13, independent review passed with no unresolved findings. This package brought six small pieces of the native reader chrome up to exact web parity: the play and pause glyphs, the visualization mode pill, the progress bar fill, the chrome and header fade easing, the progress and scrubber typography, and slider accessibility on both tracks.

## What this fixed

Before this pack, several bits of reader chrome drifted from the web. The play and pause glyphs were solid white shapes instead of hollow outlines, the visualization pill snapped between modes and fired a stray haptic, the progress fill jumped word by word rather than gliding, the chrome and header fades used reanimated's default curve instead of the web's ease out, the progress labels and the scrubber peek rendered in the wrong typefaces, and neither track was reachable by TalkBack. Each of these was a small, surgical fix that closed the gap without touching anything the approved reader feel already owned.

## What changed

### 1. Play and pause glyphs render as stroke outlines, not solid fills

The web coral play button (`p-5`, `rounded-full`, `shadow-lg shadow-coral-accent/30`) renders lucide `Play`/`Pause` at 32px (`w-8 h-8`) with lucide defaults: `stroke='currentColor'` (white), `fill='none'`, 2px stroke weight, and `ml-1` (4px) on `Play` for optical centering. Native was passing `fill="#fff"` on both icons, so they rendered as solid filled glyphs while size 32, color `#fff`, padding 20, `marginLeft: 4` on `Play`, and the shadow already matched. The fix removed `fill="#fff"` from both `Pause` and `Play` in `PlaybackButtonRow`; lucide-react-native defaults to stroke only, so the glyphs now render as white 2px outlines. Size, color, marginLeft, and shadow were left untouched.

### 2. Visualization pill animates over 200ms and drops the extra haptic

Each web mode button carries `transition-all duration-200`, so the coral background, white icon, `shadow-lg`, and `scale-105` of the active pill animate in over 200ms on a mode change. The order and icons are Focus=`Eye`, Ghost Trail=`ScanLine`, Sentence=`AlignLeft`, Paragraph=`AlignJustify`, Hybrid=`Layers`, all size 20, in an espresso 6% pill with 8px gaps, and the web fires `onActivity` then `onChangeVisMode` with no haptic. Native was firing `haptics.tick()` on the mode `onPress` and applying the active styling (accent background, `scale: 1.05`, elevation/shadow) instantly as a plain conditional style. The fix removed `haptics.tick()`, keeping the order `onInteract()` then `setVisMode(key)` (the now unused haptics import in `ReaderChrome.tsx` was removed), and extracted a `ModeButton` component whose shared value, driven by `active`, tweens the background color (accent at alpha 0 to `t.accent`, via `interpolateColor`) and scale (1 to 1.05) over 200ms with the reused `PRESS_EASE` curve. The icon color swap (white when active, `t.textMuted` otherwise) and the active shadow stayed instant.

### 3. Progress bar fill glides 75ms per word, knob still steps

The web coral fill inside the 8px rail has `transition-all duration-75`, so each word advance eases the width over 75ms for a subtle glide during playback, while the 16px knob (`ring-2 ring-cream`, `shadow-md shadow-coral-accent/40`) has only `transition-transform` so its `left` moves stepwise. Native had both the fill width (`width: `${chapterInfo.progress}%``) and the knob `left` as plain style props re-rendered on every index change, so both stepped instantly; the knob already matched web, only the fill differed. The fix added a progress shared value in `Controls` retargeted with `withTiming(progress, { duration: 75, easing: PRESS_EASE })` on every change, and replaced the inner fill `View` with an `Animated.View` carrying an animated percent width. The knob's `left` stayed a plain style prop, stepping instantly like the web. (Not changed here, noted for a later shadow pass: the web knob shadow is coral tinted `shadow-coral-accent/40` while native still uses `shadowColor: '#000'` on both knobs.)

### 4. Chrome fade and header collapse use the web's ease out curve

The web selector and controls fade with `transition-opacity duration-300 ease-out`, and the header collapses `grid-template-rows` 1fr to 0fr plus opacity with the same 300ms `ease-out`. The timing triggers, fade out 100ms after play starts, back instantly on pause, and re-hide 3000ms after the last peek or activity, were already matched on native (`PLAY_FADE_DELAY_MS` 100, `IDLE_TIMEOUT_MS` 3000) and were left alone. Native's `withTiming(..., { duration: 300 })` had no easing option, defaulting to `Easing.inOut(Easing.quad)`, a slower start with a different feel. The fix passed `easing: Easing.bezier(0, 0, 0.2, 1)` at 300ms in `src/screens/ReaderScreen.tsx` (the chrome fade). `src/components/InnerPageHeader.tsx` already carried this exact easing from a previously committed pack, so no edit was needed there. The curve differs from the prompt's stated `cubic-bezier(0, 0, 0.58, 1)`; see Judgment calls.

### 5. Progress labels in Inter, peek snippet in Inter italic, kicker letterspacing 0.3

The web body font is Inter. The progress readout row under the bar ("<Chapter title>: word X of Y" on the left, "NN%" on the right) is Inter 400 14px in mocha. The scrubber peek snippet (first 9 words as a curly quoted string with an ellipsis, or an em dash when empty) is Inter 400 italic 14px mocha with truncate. The peek chapter kicker above it is Inter 500 12px uppercase coral with `tracking-wide`, which is 0.025em, meaning 0.3px letterspacing at 12px. Native was rendering the two label `Text`s with no `fontFamily` (Android's default Roboto), the snippet in `FONTS.serifItalic` which maps to `Fraunces_400Regular_Italic`, and the kicker in `FONTS.sansMedium` but with `letterSpacing: 0.6`, double the web's 0.3. The fix set `fontFamily: FONTS.sans` on both progress label `Text`s, switched the snippet from `FONTS.serifItalic` to `FONTS.sansItalic`, and changed the kicker `letterSpacing` from 0.6 to 0.3. The `sansItalic` entry already existed in `src/theme.ts` and `Inter_400Regular_Italic` was already in `App.tsx`'s `useFonts` map, so no font loading changes were needed. The copy, the 9 word slice, the curly quote characters, and the em dash fallback already matched exactly; this was purely typeface and spacing.

### 6. Both tracks announce as adjustable sliders to TalkBack

The web main progress track is `role='slider'` with `aria-label='Chapter Progress'`, `aria-valuenow={chapterInfo.currentInChap}`, `aria-valuemin={1}`, `aria-valuemax={chapterInfo.totalInChap}`, and `tabIndex={0}`. The scrubber track is `role='slider'` with `aria-label='Scrub by paragraph'`, `aria-valuenow={peek.pIdx}`, `aria-valuemin={0}`, `aria-valuemax={Math.max(0, paragraphs.length - 1)}`, and `tabIndex={0}`. Native had both tracks as bare `Animated.View`s inside `GestureDetector`s with no accessibility props, so TalkBack users could not perceive or adjust either one. The fix added to the main track `accessibilityRole="adjustable"`, `accessibilityLabel="Chapter Progress"`, and `accessibilityValue={{ min: 1, max: chapterInfo.totalInChap, now: chapterInfo.currentInChap }}`, and to the scrubber track `accessibilityRole="adjustable"`, `accessibilityLabel="Scrub by paragraph"`, and `accessibilityValue={{ min: 0, max: Math.max(0, paragraphs.length - 1), now: peek.pIdx }}`. The `accessible` prop was also set on both so TalkBack can actually focus them, the parity match for the web's `tabIndex={0}`.

## Judgment calls

1. **Easing curve value.** The prompt named `Easing.bezier(0, 0, 0.58, 1)`, calling that CSS `ease-out`. But the web classes are Tailwind utilities, and Tailwind 3.4 (confirmed in the web repo's `package.json`, with no `transitionTimingFunction` override in `tailwind.config.js`) maps `ease-out` to `cubic-bezier(0, 0, 0.2, 1)`. The already committed `InnerPageHeader` fix uses exactly that curve with a comment explaining the same reasoning, so `Easing.bezier(0, 0, 0.2, 1)` went into `ReaderScreen.tsx` to match the real web behavior and keep both fade sites consistent, rather than the prompt's stale value.
2. **Animation easing for the pill and fill.** The 200ms pill and 75ms fill animations were passed the repo's existing `PRESS_EASE` constant (`cubic-bezier(0.4, 0, 0.2, 1)`, Tailwind's default transition curve) instead of leaving reanimated's default easing, because the web's `transition-all` utilities use that curve; the prompt's examples simply omitted easing.
3. **Pill background alpha, not transparent.** The pill background interpolates from `t.accentA(0)` (the accent color at zero alpha) to `t.accent` instead of the literal `'transparent'`, so the tween keeps the coral hue while fading in rather than passing through a grey tint.
4. **The `accessible` prop on both tracks.** This went in beyond the exact props listed, because on Android a View with only `accessibilityRole` is not focusable by TalkBack; without it the required announcement never happens.
5. **Version bump.** The state update mentioned preserving an uncommitted `app.json` bump from 0.7.2 to 0.7.3, but the working tree was actually clean at version 0.7.6, so there was nothing to preserve; per the standing rule, `expo.version` was bumped to 0.7.7 for this change round.
6. **No `App.tsx` or `src/theme.ts` changes.** None were needed: the typography pack had already landed `sansItalic` in `FONTS` and `Inter_400Regular_Italic` in the `useFonts` map.
