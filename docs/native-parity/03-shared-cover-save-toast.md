# Native parity 03: shared components (BookCover, save ribbon, skeleton, toast)

**Done.** Implemented and committed as `30a2cd4` on `feat/native-ui-web-parity`, 2026-07-13, independent review passed with no unresolved findings. This package brought four shared visual pieces of the native app to parity with the web: the generated BookCover, the leather save ribbon, the CoverSkeleton placeholder, and the confirmation Toast.

## What this fixed

Before this, the native versions of the shared components drifted from the web in ways that showed up across the whole app, on covers, on the save ribbon, on loading placeholders, and on the little save confirmation bubble. Generated cover titles were sized by a width formula that oversized shelf cards and undersized row covers, the ruled page under a peeling cover only filled its top half, loading covers painted a solid gray block instead of letting the page show through, the leather ribbon had no grain and read flat, the ribbon's touch zone did not track its saved bounds so a saved drape could unsave and open at once, the toast dropped the full entry distance on exit, and the skeleton placeholders never pulsed. Nine issues, each fixed to the web's exact constants.

## What changed

**1. Generated cover title size is fixed, not scaled by width.** The web sizes cover titles per size prop, `sm` = 11px and `md` = 15px, regardless of rendered width, with the eyebrow (7px sm / 8px md) and author (8px sm / 10px md) fixed too, and `leading-tight` (line height 1.25) on the title. Native had been computing `titleSize = sm ? Math.max(9, width * 0.125) : Math.max(11, width * 0.104)`, which happened to match at width 144 but became about 18.3px on 176px shelf cards and dropped to 9px on 48px sm rows. It is now `const titleSize = sm ? 11 : 15;` with `lineHeight` of `titleSize * 1.25` set inline on all three variant titles (solid, label, framed). Eyebrow and author were already fixed at 7/8 and 8/10 and matched.

**2. Ruled page lines fill the whole revealed region.** The web draws `repeating-linear-gradient(to bottom, rgba(107,85,68,0.30) 0 1px, transparent 1px 6px)` at opacity 0.5 across a region inset 14% top and bottom, 40% left, 10% right, so a 1px line every 6px fills the entire region at any cover height. Native had rendered exactly 14 one-pixel Views with marginBottom 5, only 84px of lines, so on a 144px cover the lower half of the peeled page was blank. `RuledLines` now takes the cover height and renders `Math.ceil(height * 0.72 / 6)` lines (0.72 because 14% is inset top and bottom), keeping the 1px line, 5px gap, and `rgba(107,85,68,0.30)` color. A 144 wide cover now gets 26 lines (156px) covering the whole 155.5px region, clipped by the existing `overflow: 'hidden'`.

**3. Cover accessory inks: pinned, with the solid on-tint fix applied.** This was originally a divergence: the web resolved cover inks against the theme, which drew label text cream-on-white and nearly unreadable in dark mode, and native pinned the inks to fixed light-mode colors. It has since been reconciled by porting the pinning back into the web `BookCover.tsx`. Native matches the pinned colors exactly: stitches and spines at `rgba(251,245,234,0.4)` and `rgba(58,42,30,0.2)` / `rgba(58,42,30,0.15)`, label author text `#6B5544`, label title text `#3A2A1E`, page edge and gutter shadow `rgba(58,42,30,0.1)` and `rgba(58,42,30,0.15)`. The uncontested part of the issue was applied here: the solid variant's on-tint text (text, rule, and Leaf) is now `t.surface` in both light and dark mode for every tint.

**4. Cover image loading face, fade, and fetch priority.** On the web a loading cover has no background (`coverBg = ''`) so the ruled page and gutter shadow show through, the img pops in with no transition, and `loading` is `'lazy'` except on three hero slots that get `priority` (eager plus `fetchPriority="high"`). Native had painted a solid `t.surfaceSunken` block while loading and crossfaded the image in with `transition={150}`. Now `coverBg` is `'transparent'` while the image shows, `transition` is `0` so the image pops in, and a `priority?: 'high' | 'low'` prop (default `'low'`) feeds expo-image's `priority`. `priority="high"` is passed at the three native hero call sites: the resume hero and today's pick hero in `TodayScreen.tsx`, and the vibe hero pick in `VibeScreen.tsx`. `cachePolicy="disk"` was left alone as the right native translation of the browser HTTP cache.

**5. Failed cover flag resets when the URI changes.** The web tracks failure as the failed URL string, not a boolean, so `showImage = !!coverUrl && failedUrl !== coverUrl` retries automatically when a mounted BookCover is handed a different URL. Native had a `const [failed, setFailed] = useState(false)` that was set true on error and never reset, so a recycled row or rotating hero slot kept the generated fallback forever. It now tracks `failedUri` as a string: `const [failedUri, setFailedUri] = useState<string | null>(null)`, `showImage = !!uri && failedUri !== uri`, and `onError={() => setFailedUri(uri!)}`. The string comparison self-resets exactly like the web, no effect needed.

**6. Leather ribbon grain texture (baked PNGs) and drape shadow blur.** The web rasterizes the strap once per theme to a 120x278 PNG (3x of the 36px on-cover width, viewBox 64x148) from an SVG that layers a base fill (`#6e4a2b` light, `#e7ddc9` dark) through a feTurbulence fractalNoise grain (baseFrequency `0.5 0.55` light / `0.42 0.46` dark, numOctaves 4, seed 11) lit by feDiffuseLighting (surfaceScale 1.7 light / 1.05 dark, diffuseConstant 1.05, lighting color `#ffffff`, distant light azimuth 235, elevation 58 light / 60 dark) blended multiply, plus the sheen gradient, loop highlight, fold shade, edge stroke (`#34200f` / `#9a8a6c`, opacity 0.55, width 1.6) and dashed stitching (`#ecd7a8` / `#5d3f23`, width 1.7, dasharray `3 3.4`). Native had drawn the paths with react-native-svg but no grain layer at all. The two themed PNGs were baked offline with `@resvg/resvg-js` from the web's `leatherSvgMarkup()` (turbulence grain plus diffuse lighting rendered correctly, both PNGs visually inspected with the grain clearly visible, about 50KB each), bundled at `assets/bookmark-light.png` and `assets/bookmark-dark.png`, and rendered via expo-image at width RIBBON_W (36) and height `RIBBON_W * 148 / 64` (83.25) inside the same clip-window reveal animation, replacing the old SVG component. The drape's cast shadow, which the web blurs with `filter: blur(3px)`, was softened by widening the radial gradient falloff: peak 0.30, mid stops 0.16 and 0.05, transparent at the rim, rx/ry widened to 58%/62%.

**7. Ribbon touch exclusion zone tracks the live saved bounds.** On the web the ribbon button stops propagation for its full live bounds: width 36 at left 16%, edge = `40 * 36 / 64` = 22.5 (tip pokes 22.5px above the cover top), unsaved height `edge + 14` reaching 14px below the cover top, saved height `148 * 36 / 64` = 83.25 reaching 60.75px below the cover top. Native's exclusion zone had been a fixed `y <= 36` band, which left two bugs: when saved the ribbon Pressable extended about 60.75px below the top so touches from y 36 to 68.75 hit both the ribbon and the card gestures (unsaving and opening at once), and when unsaved the Pressable only reached about 22px so y 22 to 36 was a dead strip. `RIBBON_HITBOX` was extended with `belowCoverUnsaved: 14`, `belowCoverSaved: 60.75` (`((VIEW.h - EDGE) * RIBBON_W) / VIEW.w`), and `hitSlop: 8`. In `BookCard.tsx`, `inRibbon` now reads `useStore.getState().savedById[book.id]` imperatively (keeping the gesture memo stable) and gates y at 22 when unsaved and 68.75 when saved (144 card x band 15.04 to 67.04). Both the lift and tap gestures share the check.

**8. Toast exit motion: drop 8px, ease out.** The web `toastPop` runs 2.4s with the CSS `ease-out` keyword (`cubic-bezier(0, 0, 0.58, 1)`), entering from translateY(16px) and opacity 0 to 0 and 1 by 12% (288ms), holding to 85% (2040ms), then fading while moving to translateY(8px), so the exit drop is half the entry distance. Native had matched the timing envelope but tied translateY to `(1 - visible.value) * 16`, dropping the full 16px on exit with the default in-out easing. translateY now has its own shared value (16 to 0 over 290ms, hold 1750ms, 0 to 8 over the 360ms fade), and every withTiming uses `Easing.bezier(0, 0, 0.58, 1)`, inside the same 2.4s envelope. Pill metrics, colors, medallion, 13px semibold text, and bottom `max(28, inset + 16)` already matched.

**9. CoverSkeleton pulse and Today shelf sizing.** The web CoverSkeleton is a 144px block (cover aspect 2:3, rounded left 3px and right 12px, background espresso at 0.07; a 12px title bar at 75% width with 10px top margin; a 10px author bar at 50% width, espresso at 0.05, 6px top margin) running Tailwind's `animate-pulse` (opacity 1 to 0.5 to 1 over 2s, `cubic-bezier(0.4, 0, 0.6, 1)`, infinite), and on the Today Popular shelf four skeletons render inside 176px snap slots while each skeleton stays 144px. Native had drawn the static blocks with no pulse and passed `width={176}` so the skeleton filled the whole slot. The skeleton is now wrapped in an Animated.View whose opacity loops 1 to 0.5 to 1 over 2s with `Easing.bezier(0.4, 0, 0.6, 1)` on both halves and `withRepeat(..., -1)`, and Today's four shelf skeletons render at width 144 inside 176px slot Views. ResultsScreen's grid skeletons (already 144) picked up the pulse for free.

## Judgment calls

- Issue 3 was resolved per the instructions for this run: the native pinned label and page inks stay pinned, and only the solid cover's on-tint color changed to the surface token in both modes. The web still needs a follow-up task to port the pinning back so the two apps match, and that reminder was recorded.
- Drape shadow blur (issue 6) was approximated by widening the radial gradient falloff (lower peak, two mid stops, transparent stop at the rim, slightly larger radii) rather than baking a separate blurred shadow image. It reads as a diffuse soft edge without a runtime blur filter, but the exact stop values are a judgment call to eyeball on the phone.
- The baked strap PNG renders through expo-image with contentFit fill at 36 by 83.25, keeping the exact geometry the old SVG used, so the clip reveal animation needed no changes.
- In BookCard the saved state is read imperatively inside the touch check rather than subscribed, exactly as specified, so the gesture memo stays stable.
- ResultsScreen's skeletons also gained the pulse since CoverSkeleton is shared, which matches the web, where skeletons pulse everywhere.
