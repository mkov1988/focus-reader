# App identity, page washes, and shell spacing

**Done.** Implemented and committed as `d34a4d3` on `feat/native-ui-web-parity`, 2026-07-13, independent review passed with no unresolved findings. This package brought the native Android app's shell up to exact parity with the web in six places: the launcher identity, the warm radial page washes, PageShell's bottom padding, the end of scroll whitespace on vibe pages, and a smooth color fade when the theme or light or dark mode changes.

## What this fixed

Before this work the native shell still wore the default Expo template. The launcher showed the raw slug, the adaptive icon sat on Expo's pale blue plate, and there was no splash configuration. The warm glow behind every page was a fixed 420px band glued to the top of the viewport, so it never scrolled away and its geometry only approximated the web. The More pages drew both glows instead of just the mustard one, PageShell added 16px of bottom padding the web does not have, vibe pages ended 28px short of the web's breathing room, and every theme or light or dark switch snapped instantly. The package matched all six surfaces to what the web actually renders.

## What changed

**1. App identity (name, adaptive icon color, splash).** The launcher used to show the raw slug because `expo.name` and `expo.slug` were both `focus-reader-android`, the adaptive icon plate was Expo's default pale blue `#E6F4FE`, and there was no splash block at all. The web PWA manifest brands the app as name `Focus Reader`, short_name `Focus Reader`, description `A calm, focused reader for public-domain books.`, theme_color `#3a2a1e` (espresso), background_color `#f3ead9` (warm beige), display `standalone`. `expo.name` is now `Focus Reader` with the slug left untouched, the adaptive icon plate is warm beige `#F3EAD9` (espresso `#3A2A1E` was the acceptable alternative), and the `expo-splash-screen` plugin was added referencing `./assets/splash-icon.png` on a `#F3EAD9` background. The stock blueprint `adaptiveIcon.backgroundImage` was removed so the beige plate can actually show, and the existing uncommitted `predictiveBackGestureEnabled` entry was preserved. Icon foreground, monochrome, and splash art remain stock Expo placeholders, which the prompt said not to redraw since the web has no branded icon to copy (its favicon is still stock vite.svg).

**2. Washes scroll away with content and use page scale dimensions.** The old `PageWash` was an absolutely positioned 420px tall SVG rendered behind the ScrollView, so the glow stayed pinned to the viewport top while content scrolled over it, and its ellipse geometry only approximated the web. The web storefront div carries two background radial gradients sized against the full page element: mustard `radial-gradient(120% 80% at 50% -10%, rgba(212,154,63,0.10), transparent 55%)` plus coral `radial-gradient(90% 60% at 100% 0%, rgba(194,103,75,0.07), transparent 50%)`, so the glow scrolls up and away with the content. `PageWash` now renders inside the scroll content as a zero height first child slot, so the glow slides off with the page. Geometry matches the web exactly: mustard 120% width by 80% page height at (50%, minus 10%), coral 90% by 60% at (100%, 0%), with page height measured from the ScrollView content and floored at the window height. Colors and stops were already correct and were kept: washA `#D49A3F` at opacity 0.10 fading to 0 at stop 0.55, washB `#C2674B` at opacity 0.07 fading to 0 at stop 0.5. The wash stays behind the content and does not block touches (`pointerEvents="none"`). Results, being a virtualized FlatList, puts the wash in its list header sized on the window floor.

**3. Stats, Settings, and About get only the mustard wash.** `PageShell` always drew both ellipses on every screen, including the three More pages. The web's More overlays use only the mustard gradient: `OverlayPage` and the Stats layer both set `backgroundImage: 'radial-gradient(120% 80% at 50% -10%, rgba(212,154,63,0.10), transparent 55%)'` with no coral top right wash. `PageWash` and `PageShell` gained a `wash?: 'single' | 'double'` prop defaulting to `'double'`, and StatsScreen, SettingsScreen, and AboutScreen now pass `wash="single"` so the coral `#C2674B` ellipse is omitted there.

**4. PageShell bottom padding formula.** PageShell's ScrollView `contentContainerStyle` used `paddingBottom: Math.max(48, insets.bottom + 16)`, which gave up to 16px more bottom padding than the web on devices with a tall bottom nav bar. The web uses `paddingBottom: 'max(3rem, env(safe-area-inset-bottom))'`, that is max(48px, inset) with nothing added on top. The formula is now `Math.max(48, insets.bottom)`, and ResultsScreen's hand rolled copy became `28 + Math.max(48, insets.bottom)` to drop the same extra 16. The two formulas are identical when `insets.bottom <= 32`, so the change only shows on taller nav bars.

**5. Vibe pages end with 76px of whitespace.** VibeScreen rendered its children straight into PageShell with no trailing margin, so the end of scroll gap was just PageShell's 48px. The web vibe content is a `<section className="mb-7">` (28px bottom margin) inside a main padded `max(3rem, env(safe-area-inset-bottom))`, so the end of scroll gap is 28px + 48px = 76px. All VibeScreen content is now wrapped in a View with `marginBottom` 28, mirroring the web's `mb-7`, on top of the corrected 48px shell padding.

**6. 300ms theme cross fade.** `useTheme()` returned plain color strings, so every backgroundColor and color re-rendered to the new value in one frame and the whole app snapped instantly. The web body element carries `transition: background-color 0.3s ease, color 0.3s ease`, so when the CSS variables are rewritten on a theme or mode change the page background and default ink cross fade over 300ms. A new `useThemeFade` hook in `src/theme.ts` drives the page shell background through `interpolateColor` with `withTiming` 300ms on the CSS ease curve `bezier(0.25, 0.1, 0.25, 1)`. A second switch mid fade snapshots the color currently on screen as the new start, so it always lands exactly on the new palette. It is applied in PageShell and the Results root, and the reader keeps its own plain colors so nothing double animates.

## Judgment calls

1. Removed `expo.android.adaptiveIcon.backgroundImage` (the stock pale blue blueprint PNG), because Android uses the image instead of the color when both exist, so keeping it would have made the beige plate invisible. Foreground and monochrome stock art were kept.
2. Installed `expo-splash-screen ~31.0.13` via `npx expo install`, since the config plugin cannot resolve without the package. Used the template defaults (imageWidth 200, resizeMode contain) with the warm beige background, verified with `npx expo config --type prebuild`.
3. Bumped `expo.version` 0.7.8 to 0.7.9 per the standing version bump rule. The tree was clean at 0.7.8 at the start, so nothing was overwritten.
4. The fade animates the page background only, not a default text color. React Native has no inherited body text color, every Text already sets an explicit theme color, and on the web those same texts snap too because their colors come straight from the CSS variables. Background only is the faithful twin of the web's body layer fade.
5. On Results the wash is sized on the window height floor because the Browse list is virtualized (988 cards, tens of thousands of pixels of content), so content height sizing would allocate an absurd SVG. `removeClippedSubviews` was set to false on that FlatList so Android does not clip the header slot's overflowing glow early.
6. The wash starts at the top of the scroll content, just below the header, whereas the web's gradient origin includes the header band. Both headers are opaque theme background on both platforms, so the only difference is the glow sitting a header height lower, accepted as the clean approximation.
7. The SVG canvas is capped at 35 percent of the page height, the point past which both gradients are fully transparent, so tall pages do not allocate huge empty layers.
